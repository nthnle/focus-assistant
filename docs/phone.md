# Phone, status page and presence

Three services that talk to your phone or browser over your home network:

- the **[phone dock](#phone-dock)**, which notices when you pick up your
  phone during focus time
- **[chat](#chat)** with the coach from your phone, typed or through Siri
- the **[status page](#status-page)**, which shows your day in any browser

and **[presence](#presence)**, which uses the dock to tell whether you're
at the desk.

The phone parts use **iOS Shortcuts**. Android with an automation app that
can send HTTP requests (Tasker, for example) should work the same way, but
it's untested.

## How the network services are protected

- They answer **private (home network) addresses only**.
- Each has **its own random token**, generated by `install.sh` into
  `/etc/focus-assistant/focus.env`. Requests without it get a 403.
- Requests are **plain HTTP**, so a token is only as private as your Wi-Fi.
- Of these, only chat holds the API key. The dock and status page can't
  spend money.

Read a token with, for example:

```bash
sudo grep FOCUS_DOCK_TOKEN /etc/focus-assistant/focus.env
```

The examples use `focus.local` as the Pi's address. If your phone can't
resolve `.local` names, use the Pi's IP address (`hostname -I`).

## Phone dock

During a focus block (`FOCUS_BLOCKS`, default 09:00-12:00 and 13:00-17:30 on
weekdays), taking the phone off its charger for more than 30 seconds logs a
**phone out** event, and putting it back logs **phone in** with the minutes
it was gone. Quick glances are ignored. The coach sees these at the next
check-in, and the status page counts the pickups.

There's no sensor: the **iPhone reports it**, through a Shortcuts
automation that runs when it connects to or disconnects from power. It works
with wireless chargers, and anything else on the same charger (a watch, for
example) is ignored.

**On the Pi:**

```bash
sudo systemctl enable --now focus-dock
TOKEN=$(sudo sed -n 's/^FOCUS_DOCK_TOKEN=//p' /etc/focus-assistant/focus.env)
curl -i -X POST -H "Authorization: Bearer $TOKEN" http://localhost:8765/dock/out   # expect 204
curl -i -X POST -H "Authorization: Bearer $TOKEN" http://localhost:8765/dock/in
```

**On the iPhone,** create two shortcuts in the Shortcuts app (tap **Edit**
to build them by hand):

- **Dock Out:** one **Get Contents of URL** action with the URL
  `http://focus.local:8765/dock/out`. Expand it, set **Method** to `POST`,
  and add a header `Authorization` with the value `Bearer <token>`.
- **Dock In:** the same, with `/dock/in`.

Run each once by hand. If iOS asks to let Shortcuts find devices on your
local network, allow it (or later: Settings > Privacy & Security > Local
Network > Shortcuts).

Then, in the **Automation** tab, add two **Charger** automations:

- **Is Disconnected**, **Run Immediately**, **Notify When Run** off, running
  **Dock Out**
- **Is Connected**, the same, running **Dock In**

Away from home the request fails silently. To avoid error banners, wrap the
action in an **If** with **Get Network Details** (Wi-Fi, Network Name) equal
to your home network.

**Check it:** `journalctl -u focus-dock -f`. Every report logs a
`Charger: in/out (...)` line saying whether it counts; `Rejected ...` means
a wrong token; no line at all means the request never arrived.

> **Battery:** keeping a phone on a charger all day is fine with **80%
> Limit** (iPhone 15 and later) or **Optimized Battery Charging** turned on,
> in Settings > Battery > Charging.

## Chat

Message the coach from your phone: "I finished the spec, what's next?", "add
email Sam", "move the report to the top", "I'm drifting". It sees the same
data as a check-in, and it can change your priorities through a fixed set of
tools (add, complete, reopen, drop, move, report). It can't do anything
else. Today's conversation is kept, so follow-ups work, and the next
check-in sees it.

Because this service holds the API key, a leaked chat token could spend
money. `FOCUS_CHAT_DAILY_LIMIT` caps it at 50 messages a day, and each
message is at most six model calls.

**On the Pi:**

```bash
sudo systemctl enable --now focus-chat
TOKEN=$(sudo sed -n 's/^FOCUS_CHAT_TOKEN=//p' /etc/focus-assistant/focus.env)
curl -s -X POST -H "Authorization: Bearer $TOKEN" -d '{"text": "what should I do first?"}' \
     http://localhost:8766/chat; echo
```

**On the iPhone,** make a shortcut named **Coach**:

1. **Ask for Input**: type Text, prompt `What's up?`
2. **Get Contents of URL**: `http://focus.local:8766/chat`, Method `POST`,
   header `Authorization` = `Bearer <chat token>`, Request Body **JSON** with
   one Text field `text` set to **Provided Input**.
3. **Show Result** with **Contents of URL**.

"Hey Siri, Coach" then asks what's up, takes your dictation and reads the
reply aloud. Errors (no network, daily limit) come back as a sentence.
`journalctl -u focus-chat -f` shows each message.

## Status page

A live page for any browser on your network: the latest check-in, your top
three open priorities, and a status strip: where you are in the day (focus
until 12:00, break till 11:00, next block), the next break, the phone,
whether you're away or have a check-in waiting, and today's done count,
phone pickups and breaks. It's rebuilt from your state on every request and
refreshes itself every 30 seconds. It's read-only.

The dock service serves it, so enable that first. Then open:

```
http://focus.local:8765/display?k=<FOCUS_DISPLAY_TOKEN>
```

The token goes in the URL because a browser bookmark can't send a header.
Anyone with that link on your Wi-Fi can read your priorities. On an iPhone,
Share > Add to Home Screen gives it an icon.

The upper panel mirrors the e-ink display layout ([architecture.md](architecture.md#e-ink-display)).

## Presence

So the coach doesn't talk to an empty desk: you count as **away** when the
phone has been off the dock for 10 minutes **and** the desk has been quiet
for 15 (no typing, chair or voice heard by the [voice service's
microphone](voice.md#2-voice-commands)). Only the time of the last sound is
stored, in `presence.json`; never audio. Without the voice service, the dock
decides alone.

While you're away:

- **stretch reminders are skipped** (you're already up)
- **a spoken check-in is held**, and the voice service says it within 30
  seconds of your return ("While you were away, the midday check-in said:
  ..."). The status page shows it meanwhile.

**Its blind spot:** leave your phone on the dock and walk off, and it still
thinks you're there. Tune it with `FOCUS_AWAY_PHONE_MIN` and
`FOCUS_AWAY_QUIET_MIN`;
`journalctl -u focus-stretch -u focus-checkin -u focus-voice | grep -i away`
shows its decisions.
