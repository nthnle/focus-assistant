# Chat, status page and presence

Two services that talk to your phone or browser over your home network:

- **[chat](#chat)** with the coach from your phone, typed or through Siri
- the **[status page](#status-page)**, the e-ink panel's layout in a browser,
  with a status strip under it

and **[presence](#presence)**, which tells whether you're at the desk.

Phone *use* is counted by the [desk camera](camera.md), with nothing to set
up on the phone. Chat uses one **iOS Shortcut** that you run yourself.
Android with an app that can send HTTP requests (HTTP Shortcuts, for
example) should work the same way, but it's untested.

## How the network services are protected

- They answer **private (home network) addresses only**.
- Each has **its own random token**, generated by `install.sh` into
  `/etc/focus-assistant/focus.env`. Requests without it get a 403.
- Requests are **plain HTTP**, so anyone on the same Wi-Fi could read a
  token in transit. Keep guests on a guest network, and ideally reserve your
  phone an IP in the router and set `FOCUS_ALLOWED_CLIENTS` to it: then only
  that phone is answered, token or not.
- The status page token is in its URL, so it is also in your browser's
  history and in any screenshot of the address bar.
- **Rotating a token:** delete its line from `focus.env`, run
  `sudo deploy/install.sh` (it writes a new one), and update the Shortcut
  or bookmark.
- Of the two, only chat holds the API key. The status page can't spend
  money.

Read a token with, for example:

```bash
sudo grep FOCUS_CHAT_TOKEN /etc/focus-assistant/focus.env
```

The examples use `focus.local` as the Pi's address. If your phone can't
resolve `.local` names, use the Pi's IP address (`hostname -I`).

## Chat

Message the coach from your phone: "I finished the spec", "add email Sam",
"what should I do now?", "I'm drifting". It sees the same data as a
check-in, and it can change your to-do list through a fixed set of tools:
add, rename, schedule for another day, complete, reopen, drop,
report, pause, resume, and rate the
previous reply when you tell it that one was wrong or spot on. It can't do
anything else. Ask it "how could I improve my routine?" and it suggests one
or two changes from your last week, each tied to a pattern it saw. Today's
conversation is kept, so follow-ups work, and the next check-in sees it.

Because this service holds the API key, a leaked chat token could spend
money. There's no daily message limit: each message is at most six model
calls, and the token is the protection, so keep it to your own phone. Set a
spend limit at your model host, if it offers one, as the backstop.

**On the Pi:**

```bash
sudo systemctl enable --now focus-chat
TOKEN=$(sudo sed -n 's/^FOCUS_CHAT_TOKEN=//p' /etc/focus-assistant/focus.env)
curl -s -X POST -H "Authorization: Bearer $TOKEN" -d '{"text": "what should I do first?"}' \
     http://localhost:8766/chat; echo
```

**On the iPhone,** make a shortcut named **Coach**:

1. **Ask for Input**: type Text, prompt `What's up?`
2. **Get Contents of URL**: `http://focus.local:8766/chat`, Method `POST`,
   header `Authorization` = `Bearer <chat token>`, Request Body **JSON** with
   one Text field `text` set to **Provided Input**.
3. **Show Result** with **Contents of URL**.

"Hey Siri, Coach" then asks what's up, takes your dictation and reads the
reply aloud. Errors (no network, say) come back as a sentence.
`journalctl -u focus-chat -f` shows each message (its length, or the
words with `FOCUS_LOG_WORDS=1`).

## Status page

The [e-ink panel](architecture.md#e-ink-display)'s own layout, as a live page
for any browser on your network: the latest check-in's slot and reply and
today's open items, and under them a status strip the panel doesn't have: where you are in the day (focus
until 12:00, break till 11:00, next block), the next break, the phone,
whether you're away or have a check-in waiting, and today's done count,
phone pickups and breaks. It's read-only, and live: it updates within two
seconds of any change, whether from voice, chat, the CLI, the desk camera or
a check-in.

When you mark something done after a check-in, a red line under the reply
says so straight away ("Since 16:20: done Mow the lawn"). If you marked it
by voice, phone chat or the call button, the coach then rewrites that
check-in for the list as it is now, about ten seconds later. The rewrite is
only shown, never spoken, and its cost counts with the check-ins in
`focus status`. Friday's weekly review is never rewritten, and `focus done`
from the CLI only gets the line, because the CLI can't read the API key.

The `focus-page` service serves it. Enable it, then open:

```bash
sudo systemctl enable --now focus-page
```

```
http://focus.local:8765/display?k=<FOCUS_DISPLAY_TOKEN>
```

The token goes in the URL because a browser bookmark can't send a header.
Anyone with that link on your Wi-Fi can read your list. On an iPhone,
Share > Add to Home Screen gives it an icon.

The upper panel mirrors the e-ink display layout ([architecture.md](architecture.md#e-ink-display)).

## Presence

So the coach doesn't talk to an empty desk, you count as **away** once the
[desk camera](camera.md) has seen the empty chair for 5 minutes. The camera
runs from 5 minutes before each focus block to 5 minutes after it, so every
check-in and stretch reminder gets its answer. Without a camera, or while
its service isn't running, you always count as here.

While you're away:

- **stretch reminders are skipped** (you're already up)
- **a spoken check-in is held**, and the voice service says it within 30
  seconds of the camera seeing you back ("You missed the midday check-in.
  It said: ..."). The status page shows it meanwhile. For the 17:30
  check-in, the camera stays on to watch for you for up to 2 hours; after
  that it stays on the screen, unsaid.

The same happens while you're paused (`focus pause 11:00`, or "quiet until
11" to the coach): reminders are skipped, and a check-in is held until the
pause ends. See [Pausing](../README.md#using-it).

**Its blind spots:** someone else in your chair looks like you, and so may
you, standing at the desk.

Tune it with `FOCUS_AWAY_CAMERA_MIN`;
`journalctl -u focus-stretch -u focus-checkin -u focus-voice | grep -i away`
shows its decisions.
